# ProbCrew v2 · 概率论伴学助手

> **一个主站形态的 AI 伴学助手**：学生登录后提问、刷题、看错题本与知识图谱；
> 答疑链路用 LangGraph 编排，解答带**可验证的正确性声明**（这次验证到什么程度），
> 判定链路**不调用任何模型**（确定性代码，< 1s）。
>
> 技术栈：LangGraph 编排 + FastAPI + **免构建 ESM** 前端（零 npm / 零外部 CDN）+ SymPy。
> 模型凭据与端点**由用户自己提供**（N14），因此不存在部署级的共享密钥。

## 现在能不能跑起来？

**能跑骨架。** `cd backend && python -m app.main` 起服务，浏览器打开服务地址**就是 `frontend/index.html`**（同源：不另开静态服务器、不配 CORS —— [`docs/03 §8.4`](docs/03-架构总览.md)）；本地门禁 `bash scripts/verify.sh`（v1：R-P1/P2/P3 + 契约校验①–⑦ + R-A…R-Q 的静态面 + 依赖方向 · **三态输出**，`[SKIP]` = 对象未产出）· 用例 `python -m pytest -q backend/tests`。★ **业务端点（`/api/*`）与 7 个页面属阶段门 B 的 W1–W4**，尚未产出 —— 所以现在打开看到的是外壳与路由，不是能用完的产品。★ **两档运行形态（2026-09-27 补）**：**缺省是远程托管** —— loopback 端点与明文 http **一律拒绝**；**单机形态**（答辩 / 教师自用）要由部署者**显式声明** `PROBCREW_DEPLOYMENT=single`（启动时会打印当前形态与"例外开不开"；**坏值**、以及"`single` 却对外监听"都**拒绝启动**）。★ **把它放到服务器上的步骤**（反代 · 证书 · 进程守护 · 备份调度 · 观测，含硬前置）见 [`docs/03 §8.5`](docs/03-架构总览.md)。

★ **为什么先把文档做完**：上一个仓库的实测结论是"**最热的问答接口、统一错误体、分页、作答、掌握度全无契约，每端各写各的形状**"，以及"**引擎有、通路无**"（判定引擎 521 行 / 16 项测试通过，而全仓 21 个路由里**没有一个批改端点**）。所以 v2 的顺序是：**契约先冻结，两边照着写**。

**`docs/07` §2.2 有一张"未产出清单"**，逐个列出还不存在的脚本与资产 —— 想确认某个东西该不该存在，看那张表。

## 门禁与 CI

**本地门禁**：`scripts/verify.sh`（阶段 B 产出）—— 它同时是 R-A/R-B 的静态扫描、依赖方向检查、**R-P 文档自洽检查**的入口。★ **范围分两批**：**v0** = R-P1/P2/P3 + 契约校验①–⑤；**v1（2026-09-27 · W5 第一批 + 第二批）** = 契约校验⑥⑦ · **内容资产与样例集的格式校验**（过 `content.schema.json` 的 `oneOf` · `item_id` 引用闭包 · 下界）· **`frontend/vendor/**` 本地化完整性**（许可 · 来源 · 逐件 `url()`）· **前端冒烟的静态面**（方法 = ADR-0006：静态面进门禁 · **渲染面留人工**）· R-A①② · R-B · R-D · R-E · R-H · R-K · R-Q①② · R-J/R-O · 依赖方向（`docs/03 §3.1`）· `api/` 薄 · R-F③ 对比度。★ **它是三态输出**：`[PASS]` / `[FAIL]` / **`[SKIP]`** —— `[SKIP]` = **对象未产出**（原因逐条打印，**不计入通过数**，也不是失败）⇒ **看到绿要连"未覆盖几项"一起读**（状态登记见 [`docs/07` §2.2](docs/07-文档地图.md)）。
★ **人工项怎么跑（ADR-0006 把渲染面判给人工）**：`scripts/manual_check.py` —— **本机手跑**（起服务 + 起一个 WebDriver；macOS 用**系统自带**的 `safaridriver`，**零新依赖、不进 CI**，也不是第二个门禁入口）。它实跑 ADR-0006 那一半：首次打开 `/` 的落地页 · R-F① **真实点击尺寸** · R-F② 键盘可达/焦点环/语义 · R-G **行为面**（跳转与返回键）· R-I `must_render` **是否真的上屏**（用**打桩的 `/api/me/notice`** 喂前端）· N8③ **渲染结果**的对比度。★ **它的第一次实跑（2026-09-27）就抓到两个静态门禁看不见的缺陷**：① 首次打开停在**"未知页面"**（空哈希没有落地页约定）；② 顶部品牌链接 **84×28px**，不足 N8① 的 32px —— 两处都已修，并把落地页约定写进 [`docs/02` §7.1](docs/02-系统设计.md)。
**远端 CI**：`.github/workflows/ci.yml` 的步骤表与之同源。★ **远端已于 2026-09-18 建立**（`https://github.com/sqbsayori/ProbCrew-v2`，public）**并已推送**，CI **已经真的运行过两次**（run #1 / #2）：★ **两次的结论都是 `success`，而四个实质步骤全部 `skipped`** —— `scripts/verify.sh` 还不存在，工作流的第 1 步预检打出 `::warning::` 并把"**门禁未运行**"写进 Job Summary，而**整个作业仍然是绿的**。⇒ ★ **`main` 的保护规则此时已经生效，也照样绿着放行** —— 因为 required check 拦的是"**没有检查**"，不是"**检查里有没有内容**"。⇒ **在这期间，"CI 绿"不构成门禁证据**（口径与逐步骤证据见 [`docs/05` §7.2](docs/05-分工与协作规范.md)，状态登记见 [`docs/07` §2.2](docs/07-文档地图.md)）。★★ **这个"空跑期"已经结束**（2026-09-21 · W0a 落地之后）：此后每次运行**七个步骤全跑** —— 最近一次（`main` · 2026-09-27 · PR #22 合并 · run #80）**`success`** ⇒ ★ **"CI 绿"自此可以当证据**，但**报绿仍要说清"在哪条分支上、跑了哪几步"**（`docs/05` §7.2 的第三问）。
**分支与提交**：★ 一人一分支 → 合并进 `main` 前**门禁必须绿**；提交信息格式 · **合并方式** · **"首次托管"五步**（含 `main` 的保护规则与三人写权限）与"冲突归谁解"，**一律见 [`docs/05` §7.2](docs/05-分工与协作规范.md) —— 本节只留指针，不复制参数**。**行尾由 `.gitattributes` 强制 LF** —— 本仓门禁是 shell 脚本，带 CRLF 会直接跑不起来。
