## 1. 用户不是一个人，是四个

学生项目最常见的失败是**把"学生"当成一个人**。实际上有四类人的成功标准**互相冲突**，一个界面同时讨好必然撕裂。

| 角色 | 真实处境 | 他要的 | 他**不**关心 |
|---|---|---|---|
| **S1 正在写作业的学生** | 有 deadline，现在就要这道题怎么算；**已注册**（或愿花一分钟注册） | 快、准、步骤能抄 | 读说明书、配环境、等半天 |
| **S2 备考的学生** | 要的是"我哪里不会"，以及反复练 | 薄弱点定位、能重做、有进度 | 单题的漂亮讲解 |
| **S3 任课教师** | 关心学生是否**真在学**、会不会被代做 | 能否被我看见、能否证明有效 | 架构多先进 |
| **S4 项目组 / 评委** | 关心这事有没有技术含量、能不能讲清 | 可验证、可复现的数字 | 界面好不好看 |

**关键推论**：**S1 与 S2 的诉求方向相反** —— S1 要"最快拿到答案"，S2 要"让我自己想出来"。

> ⚠️ **本仓必须承认的四条代价**（这是明账，不是"以后再说"）：
>
> **代价一 · 形态**：上一个仓库用**两种形态**化解 S1/S2 的冲突（探针服务 S1，主站服务 S2）。本仓决定**先只做主站**，探针后置 —— 因此 S1 得不到"就着屏幕上那段话提问"。需求 F1 成立、形态后置（见 §7），由 **N12** 保证主站不会把探针的路堵死。
>
> **代价二 · 门槛**：v2 的**全部学习类接口都要求登录**（F15），**不设免登录例外**。因此 S1 的"零摩擦"诉求**不被服务** —— v2 的 S1 实为"**已注册**学生"。
> 这不是懒，是**与 §5 伦理约束的正面冲突**：F5 的错因诊断是最接近"作业代写器"的能力，我们选择**不给它零摩擦入口**；且 ⑥⑦ 的持久化本就必须先有稳定身份（N6）。
> **v2 站在伦理一侧，并把这一取舍如实记账** —— 将来若有人要开免登录车道，必须先推翻这条理由，而不是"顺手加个开关"。
>
> **代价三 · 过程**：`§3` 环节③ 原文是"**逐步判定，指出第一处错在哪**"，但 v2 **不做中间步骤校验**（只收最终答案）。因此"**过程比答案重要**"这条课程性质（§2 性质 2）只能靠**提示阶梯**（F6）**部分**兑现 —— 系统给得出"你踩了哪个坑"，给不出"你第 2 步就错了"。
> 不做的理由是**它与 §5 的伦理约束方向相反**：允许逐步试错到对，等于把"作业代写器"从一个入口变成一个过程。
>
> **代价四 · 现场风险**：完整的答疑链路现在**依赖网络与用户自己提供的凭据**（N14）。上一个仓库的 ADR-0001 当初把"**答辩现场网络不可控**"列为主要动机之一，而 v2 主动放弃了"断网也能完整演示"这个保险。
> 缓解：§6 的可用性验收拆成**四条** —— **单机完整（P2）** · **单机离线（P1 本机端点，断网也可含答疑）** · **远程完整（P2）** · **降级（P3，不含答疑）**；但**降级演示不覆盖答疑**，这一点必须主动说，不能等评委问。★ **"去向"是 N15 告知文案的分界，不是这四条的划分依据（2026-09-17 改正措辞）**：四条里的**"单机完整"与"远程完整"两行 `egress` 相同（都是 `remote`）、只有部署形态不同**；而"单机形态既可能不外传（P1/P3）也可能外传（P2）"这句说的是**同一条形态横跨两种去向**（见 N15 与 `docs/02 §1.5①`）。**正确的说法**：**分档看形态与配置档（两档形态 × 三档配置），文案内容看去向** —— 去向相同 ⇒ **文案要求相同**。

## 2. 概率论这门课特殊在哪

换一门课（比如英语单词），需求会完全不同。四条性质直接决定产品形态：

| 性质 | 后果 |
|---|---|
| **答案几乎总是一个可验证的数值或表达式** | ★ **最大的机会**：正确性可以被机器证明。英语作文不行，历史论述不行，概率论行 |
| **但"过程"比"答案"重要** | 学生错的往往不是算错，而是**建模错**（把 P(A\|B) 与 P(B\|A) 搞反、漏掉完备事件组）。只给答案没用 |
| **错误高度模式化** | 贝叶斯方向颠倒、独立与互斥混淆、忽略 n 次试验的独立性……**错误种类有限且可枚举** —— 这使"错因库"成为一份**有限、可穷举、可版本化**的资产（首版规模见 §4 F20） |
| **知识点依赖关系强** | 不会条件概率就学不会贝叶斯；不会期望就学不会方差。**知识点是有向图，不是列表** |

**推论 1**：因为答案可验证，"**告诉你这个答案经过了几层验证**"能成为真卖点 —— 文科类工具做不到。
**推论 2**：因为错误模式化且有限，"**告诉你踩了哪个坑**"比"再讲一遍知识点"有效得多，而且要**从教材与教师经验整理即可，不需要任何学生数据**。
**推论 3**：因为依赖关系强，错题不能只记"这道题错了"，必须记"**这道题考了哪几个知识点**"，才能沿依赖图往上找根源。**这一条直接决定数据模型**。

## 3. 从"学生的一次挫败"倒推功能

不要列功能清单。跟着一次真实的挫败走一遍，功能会自己长出来。

```
场景：学生做到一道贝叶斯题，卡住了。

① 他不知道这题在问什么            → 需求 F17：题目能看懂 / 能结构化拆解
② 他隐约记得有个公式但想不起来     → 需求 F18：精准的公式/定理查找（不是泛泛讲解）
③ 他写了一个式子，不确定对不对     → 需求 F5：给出错因与下一步该检查什么
                                          ★ 措辞已改（2026-09-16）：v2 不做中间步骤校验，
                                            见 §1 代价三与下文说明
④ 他算完了，但答案是 0.99         → 需求 F4：即时批改 + 诊断"你把方向搞反了"
⑤ 他改对了，但不知道为什么对       → 需求 F10：解析 + 这一步的依据（教材出处）
⑥ 一周后他又错了同一类题           → 需求 F8：错题按知识点归类 + 能重做
⑦ 他连着错了三道贝叶斯题           → 需求 F9：沿知识依赖往上找，是不是条件概率就没懂
                                         需求 F11：给出复习路径，而不是"再练 10 道"
```

> **七个环节逐环都有需求落点**（横跨 ③④ 的 `F6 分级提示` 是伦理约束，见 §5；环节 ↔ ID 的完整性由此可被机械核对）。★ 原写"一一对应"，但 ⑦ 映射到 **F9 与 F11 两条**（8 个 ID / 7 个环节）—— 措辞已于 2026-09-16 修正。
>
> ★ **环节③ 的措辞已下调（2026-09-16）**：原文是"**逐步判定，指出第一处错在哪**"，但 v2 的判定只收**最终答案**，不做中间步骤校验 ⇒ 这句话承诺了一个系统给不出的东西。现改为"**给出错因与下一步该检查什么**"，并把"过程比答案重要只能部分兑现"写进 §1 的**代价三**。
> **为什么不做**：允许逐步试错到对，等于把"作业代写器"从一个**入口**变成一个**过程** —— 与 §5 的伦理约束方向相反。（这是取舍，不是能力不足。）

**七个环节，缺一环闭环就断。** 其中 ⑥⑦ 与 ①–⑤ 是**两种不同类型的需求**：

- ①–⑤ 是**单次会话内**的需求 → 无状态、可随时丢弃
- ⑥⑦ 是**跨会话**的需求 → **必须有持久化的作答记录**

> ★ **这是全篇最重要的推论**：任何声称"伴学"的工具，如果没有持久化作答记录，它其实只是个"答疑工具"。
> **"学习"这个词承诺的是时间维度上的变化，而没有记录就没有变化可谈。**
>
> ⚠️ **但"记下来"只完成了一半**：⑥⑦ 需要的是 **F7（记录）** 与 **F8（跨会话读回）**，两者**同为 MUST**。
> 只要求记录、不要求读回，会精确复现旧仓的失败模式 —— 契约完备、链路挂起。
> **日记了但打不开，等于没记**（见 §8 承诺 2）。

## 4. 需求清单

级别：**MUST**（缺了产品不成立）· **SHOULD**（缺了明显变差）· **MAY**（锦上添花）。
**"验收方式"一栏必须是可断言的动作**，不是形容词。

> ★ **与外部立项书的关系（2026-09-17 登记，未决）**：本清单**由本项目自己推导**，**没有与立项书的认领项建立逐条对照**。全仓只有 [`ADR-0002`](adr/0002-账号体系与身份口径.md) 两处提到"立项书"（:17 认领的"JWT 鉴权 + 角色权限矩阵"、:58 的"补上了立项书要求"）—— **立项书本身不在本仓**（`git ls-files` 里没有），因此**无法核对**本清单与它的差异。
> **为什么这是一条真缺口**：结题/中期验收通常**拿立项书比对**。若立项书认领的功能比本清单多，**做了的没记、记了的没做**都会在验收时显形。
> **两条可选处置（须负责人定）**：**①** 把立项书（或它的认领项清单）纳入本仓，并在本节建一张"**立项书认领项 ↔ 需求 ID**"对照表；**②** 明确声明"**本清单为准，立项书仅作历史背景**"（与 `docs/07 §5` 第 10 条"ADR 与正文冲突以正文为准"同型）。★ **在选定之前，本文不复制立项书内容** —— "两处记载"是 `docs/01` 承诺 11 要治的病。

|---|---|---|---|
| **N1** | **正确性可验证**：错误答案必须被拦住或标注 | MUST | 唯一的技术差异化。学生无法判断对错，**误信的代价由学生承担**。验收必须是**结果指标**：注入 20 道已知**系统错解**（方向颠倒 / 漏完备组 / 单位错 / n 乘错各 5 道）→ 断言被标注存疑或降级者 **≥ 18 道（90%）**。"走了重算流程"是过程指标，**可以被满足而毫无效果**。**该地板只允许上调，下调必须走 ADR**。★ **构成要求（2026-09-16 补，否则地板可被平凡满足）**：§9 的**解答级注入集** 20 道中**至少 8 道必须落在 A / B 级可达的类别上**（即 `sympy_recompute` / `symbolic_equivalence` 可施加），且这些道次的拦截方式**必须是"重算不一致"**（`docs/02 §4.4③` 的第 2、3 行），**不得全部靠"手段缺失 ⇒ 降级到 D"** —— 否则这条地板只约束了"有没有一个降级开关" |

| **N13** | **评测资产为一等交付物** | MUST | **拆成两句**（口径澄清，理由与价格见 §6 表后）：① **样例集**（小、公开，3–5 题）与**运行器**入主仓并**纳入门禁**（本地 `scripts/verify.sh`；接远端后该脚本即 CI 入口），缺失即红灯 —— 负责**防退化**；② **冻结正式集**（注入集 20 道 + 冻结验证集 + **期望判据表**）由**非实现者**保管且**不入主仓**，在阶段门 C 由非实现者执行 —— 负责**能力验收**。理由：N1 是 MUST 而其验收**完全依赖**评测资产 —— 使能项比被支撑的需求低一级属自相矛盾（与 F8 提级同一逻辑） |

| **N15** | **外传告知**：必须显著告知"提问会被发送到第三方模型服务"，设置页随时可查 | MUST | 它是 **N2 诚实**的组成部分而不是附加项 —— 诚实不只是"不编造答案"，还包括**说清数据去了哪**。**化名账号（N6）、删除权边界（F16）、审计保留三项的正当性都建立在"用户知道数据去了哪"之上**：若用户不知情，这三条就变成在替他做决定。★ **条件化（2026-09-16 新增 · 同日二次修正）**：内容 = **实际去向**（供应商名 + 是否远程）+ **载荷范围**（提问原文 + 上下文）+ **删除权边界句同屏**。★ **判据是"去向"，不是"部署形态"（二次修正）**：`egress = remote`（**P2**）⇒ 文案"**提问会发送到第三方模型服务**" + 供应商名；`egress ≠ remote`（**P1 本机端点 / P3 无凭据**）⇒ 文案"**数据不发往第三方**"。**为什么不能按形态判**：`docs/02 §1.5` 的**单机形态包含 P2**（单机 + 远程端点 + 凭据）—— 按形态判会让"单机 + 远程端点"的学生看到"数据不发往第三方"，而提问正文**正在**发往第三方，这正是 **N2 诚实**要防的事。触发粒度**每账号一次**，`notice_ack_at` **落服务端**（若只存浏览器，**换台机器就不再告知**，而机房换机器是最常见情形），**读写口见 `docs/02 §6.1`** |
| **N16** | **部署形态与端点可控** | MUST | 系统必须支持**两种部署形态**：**单机**（答辩 / 教师自用）与**远程托管**（正式服务，见 N17）。**端点与凭据由用户提供**（N14）。**单机形态下支持本机端点**（loopback）⇒ **断网可完整演示**；**远程托管形态下只有 P2（用户自配远程端点）与 P3（无凭据）两档，loopback 一律拒绝**（学生填的 loopback 是**服务器的** loopback，既无正当性也是 SSRF 面）。四条验收：① 单机 + 本机端点时**断网**走完整链路（含一次答疑）且 `qa_log.egress='loopback'`；② 设置页展示的去向与 `SELECT DISTINCT egress FROM student_qa_log` **一致**（★ **前置：该账号至少完成过一次答疑**（2026-09-16，决策 5A）—— 干净账号该查询为空，断言**既非真也非假**；P3 下设置页展示"当前无凭据、未发生外传"）；③ 远程配置下用**假 provider** 抓载荷，断言不含禁止字段（见 `docs/02 §1.5④` 载荷白名单）；④ **登出后**浏览器本地不再保留凭据与端点配置。**边界（写进格子，防误读）**：本机端点由**用户自备**（我们**不内置、不打包模型权重**）⇒ **N4 不收窄回来**，**N16 不承诺"装上就能用"**。★ **端点信任边界与 `egress` 枚举已于 2026-09-16 落进 `docs/02 §4.2.1` 与 `docs/02 §3.1`**（此前 `ADR-0005` 的 §4 定了六条，而正文零落点） |
| **N18** | **传输加密** | MUST | **远程托管形态下，凭据与令牌每天都在公网上走** —— N14 把模型凭据放在请求头里、F15 把会话令牌放在请求头里，而**没有一条需求要求这条链路是加密的**；N17 已经承诺了学生在我们的服务器上有账号，缺这一条等于只承诺"存"、不承诺"守"。验收四条：① 远程托管形态下令牌与 `X-Model-Key` **只经 HTTPS** 传输，**明文 HTTP 请求被拒**（重定向或 400 并说明）；② 前端**无任何第三方脚本 / CDN**（与"零依赖"同源，可断言 `index.html` 无外部 `<script src>`）⇒ **凭据不存在跨站外发面**；③ 单机形态（P1 + 本机访问）允许 http，但**必须与 P1 的"本机端点"显式勾选共用同一开关**（口径同 N16）；④ 响应头含 `Strict-Transport-Security`。**不做**：证书自动化与 HSTS 预加载（属部署，`docs/06` 记为脚本化部署项） |
| **N19** | **数据备份与恢复** | MUST | **N17 把学生数据放在我们运营的服务器上，就必须承诺它不会因为一次磁盘故障而消失。** F16 给了学生"删掉我的数据"的权利，却**没有任何需求保证"你不删的时候它还在"** —— 而 `.gitignore` 把 `backend/data/` 整目录排除，学生的唯一副本就在那块磁盘上。验收四条：① 备份落**部署主机本地** `backend/data/backups/`（**同机另一个卷 / 目录**，仍在 deny-by-default 内），★ **不构成第三个出网口**（见 `docs/02 §1.5③`）；② 备份内容 = **L2 的 SQLite 库**（`backend/data/*.sqlite`，编号见 `docs/03 §2`；★ **原文写"三库"，而全仓只定义了一组 `*.sqlite`**）+ `content/MANIFEST.json` 的 `rev` 快照，**不含日志**（R-O 已定日志只记 ID 与动作）。★ **取法**：开了 **WAL**（`docs/02 §3.6`）之后**不得文件级 `cp`** —— 必须用 `sqlite3.Connection.backup()` 或 `VACUUM INTO` 取**一致快照**，否则会出现"备份成功但少了最近的作答"；③ **恢复演练**：从备份恢复后 `student_user` / `student_attempt` / `student_mastery` / `student_hint_log` 的行数与备份时刻一致，且**能被登录与错题本读到**（读回断言，与 F16 同型）；④ 备份失败**可观测**（写一条只含 ID 与动作的日志，符合 R-O）；★ **备份新鲜度可查**：`/api/health` 或管理页须显示**最近一次成功备份的时间与结果** —— 只记"失败"会让"备份停了三天"看起来一切正常（health 仍只报本地事实，不构成第三个出网口）。**不做**：异地 / 多副本备份 · 在线热备 · 点对点恢复 —— 放开任意一项都须走 ADR |
| **N20** | **容量与并发** | MUST | **全文此前只有"只允许单 worker"这一句约束，没有任何容量目标** —— 而部署形态已经是"为学生提供在线服务"，于是"够不够用"无法判定、也无法排练。**承诺的规模是"一个班 / 一门课"**：约 **50 名在读学生**、**峰值 10 路并发答疑**；★ **判定 / 列表接口的口径（2026-09-16 补全，原文引"与 F4 同口径"而 F4 只约束判定链）**：**判定链路**（刷题：归一化 → 判定 → 错因匹配）在**并发 50 路**下 **P95 < 1s**，样本 = **每路同一题连续 20 次**，**固定窗口**；**列表接口**（错题本 / 进度 / 知识树）在同一并发下 **P95 < 1s**，样本 = **每路 20 次同参数请求**；两条**只对 `gradable=true` 的题目与已登录账号**统计。★ **边界写死**：**第 11 路起**并发答疑即超限，**如实返回 503**（`docs/02 §8-13g` 的断言依赖"10 路内不得 503、11 路必须 503"这一对）。验收四条：① 10 路并发答疑时 `/api/health` **仍 < 100ms**（与 `docs/02 §8-7` 同口径）；② 其中任意 5 路**中途断流** ⇒ 图被取消、**无残留任务**，剩余 5 路不受影响、`seq` 单调且 run 隔离（**这是"断开即取消"必须成立的验收**）；③ 10 路答疑 + 50 路判定的复合压测下**无 5xx、无写库冲突报错**（WAL + `busy_timeout` 生效）；④ **以上均在 `worker=1` 下通过**（单 worker 约束不放开）。**不做**：多 worker · 外部检查点存储 · 水平扩展 · 限流排队（超限**如实返回 503 并说明**，与 N2 诚实一致） |
| **N17** | **受控托管**：学生数据**只存于我们运营的服务器**，不流向第三方（**除模型调用载荷**） | MUST | ★ **2026-09-16 新增，因为最终部署形态是远程服务器**。它把三条既有需求的口径从"本地库"改写为"**受控托管**"：**N6**（化名账号：从"只落本地库"改为"只落**我们控制的服务器**"）· **F16**（删除权：从"本机全部数据"改为"**服务器上属于该用户的全部数据**"，且**不含日志文件**——日志按 R-O 只记 ID 与动作）· **审计保留裁定**（前提从"`user_id` 映射不落在系统之外"补充为"**映射不落在我们控制的服务器之外**"）。**如实声明边界**：远程托管下 **"不外传"≠"数据不出学生设备"** —— 学生数据**存在我们的服务器上**，只是不发往第三方模型服务。★ **三条改写已于 2026-09-16 落进 N6 / F16 / `docs/02 §3.1` 的正文**（此前本格只是"声明改写了"，而正文未改 —— 那是本轮 P0-2） |

## 5. 一条需求层面的伦理约束（不是功能）

**F1–F6 做得越好，工具越接近"作业代写器"。** 这是需求内在的矛盾，必须在产品层面缓解：

| 缓解手段 | 机制 |
|---|---|
| **提示阶梯（F6）** | 默认先给方向，完整解析需学生先尝试 —— 把"抄答案"变成"要点两下"的摩擦 |
| **不做"直接出最终答案"的入口** | 把"结论"放在"过程"之后 |
| **教师可见（F15 的教师角色，经管理页）** | 让 S3 知道工具在干什么，而不是被绕过 —— 落点是**已落地的管理页**（★ **学生明细逐条查看**，2026-09-16 由"班级统计"改写 —— `docs/02 §6.1` 已判定该词与 §9 的"不做跨用户聚合"**意思相反**），不是待建报表；F14 的学生自陈视图是同一目的的补充视角 |
| **如实记入掌握度** | "用了 3 次提示才答对"照实记。数据上不美化 —— **这正是 `hint_used` 字段存在的理由** |

> ★ **教师侧可见范围的正当性基础（2026-09-17 补 —— 独立审计发现这一格只写了"能看"，没写"凭什么看"）**：上表把"**学生明细逐条查看**"当作缓解手段，但**没有说学生是否被告知、依据是什么、能否拒绝**；而本表自己的"知情同意"只出现在别处（§9 与 N13 的评测语境）。**三条写死**：**① 正当性基础 = 教学管理**（S3 教师关心"工具有没有被拿去抄作业"），**不是**任何形式的评价或排名；**② 范围收窄**：管理页**只能逐条看本机范围内学生的作答与掌握度计数**，**不得产出跨学生的派生指标**（平均分 / 排名 / 分布 / 热力图 —— §9 的排除项，`docs/02 §6.1` 已按此改写）；**③ 必须告知**：N15 的告知至少要覆盖契约钉死的**三项内容**，并**建议补第四项"教师可查看你的作答明细"** —— ★ 若要把它定为**必须**，须**同步**改 `contracts/user.schema.json` 的 `noticeStatus` 描述与 `docs/02 §1.5①` 的文案列（**不能只在一处加**：那两处被契约点名为同源）。
> ★ 推论：**"提示阶梯"不是体验优化，是伦理约束落地的地方。** 它必须在数据模型里有对应字段（用了几次提示），否则约束**无法执行、也无法度量**。
> 这条把 F6 从"交互设计"提升为"必须产生数据的需求"。

## 6. 什么算"做成了"——成功标准

| 维度 | 对应需求 | 达标线 | 怎么测 |
|---|---|---|---|
| 解题正确率 | F2 · F17 | 在**冻结验证集**上 ≥ **回归基线**（首次全量测量值，于阶段门 B 结束时录入本表并冻结；**只许上调，下调走 ADR**）。**这是回归门槛，不是质量门槛** —— 它防止退化，不假装我们知道绝对水平 | 固定题集 + 固定评分脚本（测量条件见"判定准确率"行） |
| 判定准确率 | F4 | 在**冻结验证集**上、**单用户本地**、**进程已启动且首次请求已完成**的条件下：**数值题**（`answer_kind=value`）100% 由确定性代码判定；**应用题**（`answer_kind=text`）允许表达误差。★ **统计范围 = `gradable=true` 的题目**（`gradable=false` 的题不进判定链，`correct=NULL`，见 `docs/02 §3.3`） | 对照标准答案。★ **这是六条核心验收里最容易自动化的一条** —— 确定性代码对照标准答案，无需人工门禁 |
| **判定延迟** | F4 · N7 | **纯计算题**（`answer_kind=value` 且 `gradable=true`）端到端 **< 1s**；判定链路中**无 LLM 调用**。**测量样本数：同一题连续 20 次取 P95**。★ **适用范围：只约束判定链**（刷题：归一化 → 判定），**不覆盖答疑链**的生成 / 验证 / 重算 | 计时 + 调用计数断言（延迟定级以 F4 为准，N7 不重复定级） |
| **讲解首字** | N7 | 讲解首字 < 2s | 计时（这一项才需要"缓存已热"的定义：**进程已启动 + 首次同类请求已完成**） |
| **错误拦截率** | N1 · N13 | **解答级注入集**上的已知错解 **≥ 18/20（90%）** 被标注存疑或降级，**且每类（5 道）须 ≥ 4/5** —— 防整体容错掩盖单类崩盘。★ **构成要求（2026-09-16 补）**：20 道中**至少 8 道**须落在 **A / B 级可达**的类别上（`sympy_recompute` / `symbolic_equivalence` 可施加），且这些道次的拦截方式**必须是"重算不一致"**，**不得全部靠"手段缺失 ⇒ 降级到 D"** —— 否则这条地板只约束了"有没有一个降级开关"（构成口径见 N1 与 `docs/02 §9.1`）。**地板只许上调，下调走 ADR** | 冻结正式集，由**非实现者**执行（约束见下）；见 N1 |
| **错因命中率** | F5 · N13 | **答案级注入集**上的命中率 **≥ 90%**，**且每类 ≥ 4/5**。**"命中"定义为**：实际命中的错因 ID **集合 ⊇ 期望集合，且不含未期望条目**（单值比较会漏掉"一答案多错因"这种真实情形）。**必带负样本**：确实无对应错因的错误答案须输出"**未识别错因**"，**编造即红灯** | 在**答案级注入集**上统计，走**错因匹配的函数级入口**（`domain.match_mistake(normalize(answer), item)`，**归一化必须在入口内**）；见 F5 与 §6 表后 |
| **诚实性** | F3 · N2 | 一致率 **100%** | **全量断言**（不是抽查）：对每条验证报告断言 `level ≤ 手段允许的上限`（无 `sympy_recompute` ⇒ A 不可达；无 `symbolic_equivalence` ⇒ B 不可达）**且** `conf ≤ cap(level)`（上限表见附录 A 待落地项） |
| **越权隔离** | F15 | 学生 A 无法读到学生 B 的任何数据（含聚合与导出） | 越权用例：以 A 的令牌访问 B 的资源 |
| **删除读回** | F16 | ★ **统一为四类处置句（2026-09-16）**：**四张数据表**（问答流水 / 提示流水 / 作答 / 掌握度）**硬删**，读回 **0 行** · `student_token` **级联删除**，读回 **0 行** · `student_user` **脱敏**（行保留、不可登录、`notice_ack_at` 清空）· `student_audit` **保留**（**只记 ID 与动作**）。★ **显式声明：不含日志文件** —— 日志按 **R-O** 只记 ID 与动作，内容不得落盘 | 接口测试（**逐表读回**，不是"没报错"） |
| **提示阶梯生效** | F6 | 未提交前**不返回**完整解析；每次提示使 `hint_used` 精确 +1 | 接口测试 |
| 闭环完整性（MUST 部分） | **F2 · F4 · F5 · F7 · F8 · F19** | 全通（含 F8 能跨会话读到 F7 的数据）。★ **F2 是解答链的输入**（"逐步判定"的判定对象就是它），**原写法把它漏在表外** ⇒ 本条是"全通"却测不到解答是否产生 | 端到端走一遍并**刷新页面**（只写不读不算通） |

**评测资产的三条独立约束（N13 的可执行形式）** —— 防"出题人与被评人是同一批人"：

1. **冻结验证集**：从题库切出，**出题记录不进实现人视野**（执行形式见下表）；
2. **版本号 + 冻结日期**：注入集与验证集都带版本；并设**分类地板**（每类 5 道须 ≥ 4/5），防止整体容错掩盖单类崩盘；
3. **阈值不得在看到结果之后调整测法**；评测资产由**非实现者**执行。

**N13 与"完全盲测"的相容解**（刻意记账，因为它有真实价格）：

| 资产 | 存放 | 谁执行 | 自动化 |
|---|---|---|---|
| **样例集**（3–5 题 + 期望结论） | **入主仓** | 本地门禁（接远端后即 CI） | **自动红灯** —— 保住防退化价值 |
| **冻结正式集**（**解答级注入集** + 冻结验证集） | **不入主仓**，非实现者保管 | 阶段门由非实现者手工执行 | **人工门禁，不能自动红灯** |
| **运行器** | **入主仓**（`scripts/eval_verify.py`，**不含任何答案**） | 任意人（**正式集的执行结果只能由非实现者签署**） | 可 review |
| **期望判据表** | 与正式集同处，**不入主仓** | 非实现者编写 | — |

> 为什么必须这样拆：**只要注入集进了仓库，实现人就能读到**，盲测失效。★ **理由已换锚（2026-09-16）**：原写的是"离线、无密钥基础设施的前提下（ADR-0001），门禁无法从仓库外取题"—— 那个前提**已不成立**（v2 联网、且用户自持凭据）。**结论不变，但理由改成**：为一件**一次用一次**的验收，引入**外部托管位置 + 一套取题凭据**，成本高于收益；而"正式集不进仓"这条隔离要求**与能不能联网无关**。
> **为什么把"评分脚本"拆成"运行器 + 期望判据表"**：运行器本身**必须可 review** —— 否则没法确认它真的在数命中，而不是在数"没报错"。把**机制**留在仓库、把**答案**移出仓库，两个目的同时达成。
> **价格已记账**：N1 的正式验收**不能自动化**；需要**至少两人不可互换**（出题人 ≠ 判定/验证实现人）；若判定引擎只有一人实现，**此人不得参与出题**。若将来排不开人手，退路是降为"最小可行隔离"（出题人与实现人分开），届时须走 ADR 说明为何放弃盲测。
> ★ **两份具名注入物（2026-09-16 定死）** —— 上一版的"注入集"一个名字装了两种东西，导致 F5 的指标在声明的注入点上**测不出来**：
> - **解答级注入集 → 服务 N1**：注入物 = **系统错解**（一道题 + 一个已知错误的**解答**）；注入点 = **验证链的输入**（函数级、确定性、可批量）；断言 = 该解答被标注"存疑 / 不一致"或级别被降。**不走 `/practice/grade`**（那条链路只比对学生的答案，测不到"系统自己的解答对不对"；且任何错答案都会被判错 ⇒ 门禁**平凡通过**）。
> - **答案级注入集 → 服务 F5**：注入物 = **学生错答案**（一道题 + 一个已知错误的**答案** + **期望错因 ID 集合**）；注入点 = **错因匹配的函数级入口**（`domain.match_mistake(normalize(answer), item)` —— **归一化必须在入口内**，否则测的是现实中不存在的路径）；断言 = **实际命中集合 ⊇ 期望集合，且不含未期望条目**。**必带负样本**（确实无对应错因的错误答案）⇒ 断言"**未识别错因**"，防编造。
> - **端到端 3–5 条**放进**样例集层**：只承担**回归保护**（"这条链真的接上了"），**不承担 N1 / F5 的能力验收**。

> **为什么"复习有效性"不设门禁**：它需要**同一个学生反复练同一知识点**才能算出，而样本量取决于真实使用，不由我们决定。
> 因此本文只承诺**能力**（能算出来）与**诚实**（算不出时显示"数据不足"），不承诺**数值**。把它设成门禁只会逼出一个假数字 —— 那正是 N2 要防的事。
> **代价已记账**：它不是承诺，只是能力。

**一条人力规则**（**脚本查不了，只能靠人** —— 正因如此更要写下来）：

- **R-C**：内容资产（**F20**）与编排层（`graph/`）**各须有明确责任人**，`docs/05` 的责任人表**不得留空位** —— **空缺即该需求不得计为已立项**。★ **五类内容资产须至少两人分担（2026-09-16，决策 9A）**，且**资产产出必须进 `docs/06` 阶段门 B**（F5 的地板要靠它）。★ **已落（2026-09-17）**：责任人见 `docs/05 §2.2`（五类落在**三个域**，F5/F17/F18 三条流水不共用瓶颈），门与判据见 `docs/06 §7`。**为什么把"至少两人"也写进规则**：五类资产的下界是题库 ≥30 / DAG ≥40 节点 / 错因库 ≥40 / 题型 ≥15 / 公式库 ≥30，而 **F5 / F17 / F18 分别吃错因库 / 题型库 / 公式库** —— 三条需求对应三条独立的产出流水，压在一个人身上会让它们**同时**挂。

## 9. 本仓不做（明确边界）

**v2 永久不做**：npm / 打包器 · ORM · Postgres · Docker 化生产部署 · i18n · 多端适配（N10 为 MAY）。
**v2 不做（运维面已立项，但边界写死）**：**多 worker 与外部检查点存储**（单 worker 保留不放，放开须走 ADR）· **异地 / 多副本备份**（N19 只做同机备份，目标是同机另一个卷 / 目录）· **限流排队与高可用**（N20 超限**如实 503**）· **证书自动化与 HSTS 预加载**（N18 只要求加密传输与拒绝明文）。
**v2 本阶段不做（形态后置）**：注入式探针（读屏） · 划词交互 · 驱动宿主动画 · PDF 阅读器与教材溯源定位。
**v2 不做（数据门槛仍在）**：**跨用户聚合**与**教师侧建模分析**（成绩分析报表 / 掌握度热力图 / 跨班对比）—— 这些依赖真实学生数据与知情同意，**与"作答记录"是两件事**（见承诺 2，别再混为一谈）。
**本条的边界（必须写死，否则会重演旧仓的失败模式）**：本条**仅**指跨用户聚合与教师侧建模；**仅本人可见**的作答记录、掌握度与进度视图属 **F11 / F14 / F19，不受本条约束**。本机范围内的学生明细查看由管理页承担（F15 的教师角色）。
> 为什么这条边界必须写出来：旧仓的作答记录契约正是"因被归入需知情的建模线而**整体挂起**"，而错题本要的正是它。下一个接手者完全可以说"F11 的薄弱视图就是学习者建模"，然后整条线停摆 —— 这句话就是防这个读法的。
**v2 不做（无验收项）**：屏幕阅读器完整支持 —— 语言层输出无法机检，写进 MUST 会变成一扇永远红的假门禁，写 SHOULD 又假装将来会做。**不做就是不做**（见 N8）。

## 附录 B · 需求 ID 的变更规则

- **只增不改**：已有 ID 的含义不得改变；需求变了就新增 ID，旧 ID 标注"已被 Fxx 取代"并注明日期。
